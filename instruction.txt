ROBOTIC GROCERY STORE — TEST INSTRUCTIONS

This project contains three Webots worlds that use the same Python controller code from the `controllers/` folder. Each world represents a different testing scenario, but the controller stack is shared.

The three worlds are:

1. `worlds/exception_handling.wbt`
   Used for exception and failure testing.

2. `worlds/triger_threshold.wbt`
   Used for shelf and pallet threshold testing.

3. `worlds/truck_delivery.wbt`
   Used for the normal delivery and logistics flow.

All worlds use the same main controllers:

- `youbot_restocker_demo`
- `youbot_sorter_demo`
- `ipr_pick_demo`
- `scanner_controller`
- `stock_monitoring`
- `shelf_monitoring`
- `restocking_task_manager_demo`

The dashboard is also shared by all worlds. Start it with:

python dashboard_server.py

Then open:

http://127.0.0.1:8000


BEFORE STARTING A TEST

Before testing any world, do the following:

1. Start the dashboard server in a separate terminal.

2. Open only one Webots world at a time.

3. If you switch between worlds, reload the world before testing:
   File → Reload World

4. If the behavior looks strange, clear old runtime files from the `data/` folder. The most important ones are:

   - `last_failure.json`
   - `conveyor_unknown.json`
   - `spawn_signal.json`
   - `sort_queue.json`
   - `shelf_counts.json`
   - `task_manager_state.json`
   - `sim_run.json`

5. Press Play in Webots and wait around 5–10 seconds.

6. Check the console for messages such as:

   - `[SHELF MONITORING] Baseline shelf counts (peak during settle, run id=...)`
   - `[TASK MANAGER] Baseline shelf counts (from shelf_monitoring)`
   - `[TASK MANAGER] Pallet box sync at t=...`

7. Open the dashboard and confirm that shelf and stock pallet counts are visible.

Important: wait for the baseline log to show 9/9 per product before manually deleting shelf items for threshold tests. If you delete bottles while paused before pressing Play, baseline will match the reduced count and no sort will trigger.


SHARED LOGIC IN ALL WORLDS

Controller roles (observations → decisions → actions):

  shelf_monitoring
    Scans front shelves → writes data/shelf_counts.json (counts + baseline).
    Does NOT create sort tasks.

  stock_monitoring
    Counts boxes on stock pallets → writes data/pallet_counts.json.
    Does NOT create sort tasks.

  restocking_task_manager_demo
    Reads shelf_counts.json + pallet state + inventory.
    Creates sort tasks (front shelf restock), IPR spawn orders, restock queue entries.

  youbot_sorter_demo / youbot_restocker_demo / ipr_pick_demo
    Execute tasks from sort_queue.json / spawn_signal.json only.

Flow for front-shelf restock:

  shelf_monitoring → shelf_counts.json → task_manager → sort_queue.json → sorter

Front shelves:
- Each front shelf has a maximum of 9 items (3 rows × 3 items: top, middle, bottom).
- Hardcoded slot coordinates live in `controllers/youbot_sorter_demo/youbot_sorter_logic.py`.
- Sorting is triggered when one full row is missing vs the locked baseline.
- Example: if the shelf goes from 9 items to 6 items, a sort task should be created.
- Sorting should not happen if the shelf is already full (9/9).
- When the sorter restocks, it fills the first empty row (top → middle → bottom), not always the top row.
- Each new Webots run clears `sort_queue.json` (task manager assigns a new sim run id).

Stock pallets:
- Each stock pallet has a maximum of 5 boxes.
- If a pallet drops below 3 boxes, the system should request a new IPR spawn.
- After a box is spawned, the next spawn should wait until the box passes the conveyor scanner and the cooldown has finished.

The restocker moves boxes from the conveyor to the correct stock pallet.

The sorter moves products from the stock pallet to the front shelf.

Sort tasks are created only by `restocking_task_manager_demo` (one task per missing row). `stock_monitoring` reports pallet counts but does not enqueue sorts.

Product routing is based on:

data/box_routing.json

Inventory and stock state are stored in JSON files in the `data/` folder.


WORLD 1 — EXCEPTION HANDLING

Open:

worlds/exception_handling.wbt

Use this world to test failures and exceptions.

Expected saved setup:
- RubberDuck is placed on the moving cardboard-box belt.
- The world is configured for testing unknown objects, restocker failures, and sorter failures.

Quick tests:

A) Unknown object at scanner

Run the world and let the RubberDuck reach the upstream scanner.

Expected result:
- Console shows an unknown object / scanner exception.
- Dashboard shows a scanner failure.
- `data/conveyor_unknown.json` is written.

B) Restocker failure

Remove the RubberDuck first if it blocks the normal flow. Then wait until the restocker is carrying a box. Pause the simulation, delete the carried `SPAWNED_BOX_*`, and resume.

Expected result:
- Console reports a restock failure.
- Dashboard shows the restocker as the failed robot.

C) Restock success verification

Let a full restocking cycle complete.

Expected result:
- Console confirms that restock was verified on the correct stock pallet.
- Dashboard shows a `restock_complete` event.

D) Sorter failure

During an active sort task, delete the target box from the stock pallet.

Expected result:
- Sort task fails.
- `sort_queue.json` marks the task as failed.


WORLD 2 — THRESHOLD TESTING

Open:

worlds/triger_threshold.wbt

Use this world to test shelf and pallet thresholds.

Expected saved setup:
- No RubberDuck.
- Clean conveyor.
- Shelves and pallets start from a normal full-stock layout.

Quick tests:

A) Full shelf → no sort

Start the world with shelves full.

Expected result:
- Dashboard shows shelf full.
- No new sort task is created.
- YouBot Sorter stays idle (no stale tasks from a previous session).

B) Shelf row missing → sort triggered

Pause the simulation and delete 3 front-shelf items for one product, so the shelf goes from 9 items to 6 items. Resume and wait a few seconds.

Expected result:
- `shelf_counts.json` shows the lower count.
- A sort task appears in `sort_queue.json` (usually `task_type`: `front_restock` from task manager).
- YouBot Sorter starts moving products from stock pallet to front shelf.
- Bottles are placed on the empty row (e.g. middle row if that is what you deleted).

C) Stock pallet low → IPR reorder

Pause the simulation and delete boxes from one stock pallet until only 2 remain. Resume the simulation.

Expected result:
- Dashboard shows the pallet as 2/5.
- Task manager requests an IPR spawn.
- `spawn_signal.json` is updated.
- IPR spawns a new `SPAWNED_BOX_N`.

D) Stock pallet full → no reorder

Leave a pallet at 5/5 boxes.

Expected result:
- No new IPR spawn request is created.

E) Spawn cooldown

After an IPR box spawn, wait until the box passes the conveyor scanner. The next spawn for the same product should only happen after the cooldown period.

Expected result:
- No instant repeated spawning.
- New spawn happens only after the configured delay.

Expected result:

TROUBLESHOOTING

If the dashboard shows `- / 5` for a stock pallet:
- Reload the world.
- Check that `shelf_monitoring` and `restocking_task_manager_demo` are running.

If the restocker never picks:
- In the exception world, check whether the RubberDuck or `conveyor_unknown.json` is blocking the conveyor.
- Delete the duck or remove `data/conveyor_unknown.json`.

If the dashboard shows an old failure:
- Reload the dashboard.
- Check or delete `data/last_failure.json`.

If the sorter moves at startup with full shelves (9/9):
- Reload World and clear `data/sort_queue.json` (also cleared automatically on each new sim run).
- Wait for `[SHELF MONITORING] Baseline shelf counts (peak during settle)` before judging behavior.

If sort fills the wrong shelf row:
- The sorter scans empty slots and fills the first empty row (top → middle → bottom).
- Delete a full row (3 items), not scattered single bottles, for predictable restock placement.

If motor limit warnings appear at startup:
- They are usually harmless.
- The controllers clamp joints after startup.
